# First Game

## Общие правила разработки

- В этом разделе храним согласованные с пользователем правила, которые применяются ко всему проекту. Рабочие варианты обсуждаем в карточках Notion и записываем сюда после согласования.
- Если для задачи не хватает продуктового или технического решения, сначала согласуем его с пользователем. Черновики, результаты разовых запусков и предложения из аудита сами по себе не устанавливают правила проекта.
- Разработка игры ограничена клиентом Unity, локальными данными и инструментами Unity Editor. Правила работы агентов и ведения задач TowerDefence описаны в [AGENTS.md](AGENTS.md).

## Согласованные требования к первой версии

- Целевые платформы — веб, Android и iOS.
- Для веб-сборки проверяем текущую и предыдущую стабильные версии Chrome, Edge, Firefox и Яндекс Браузера на ПК, Safari на macOS и iOS, Chrome на Android. Браузер должен поддерживать WebGL 2.0 и WebAssembly.
- Нативные сборки поддерживают Android 8.0 и новее (API 26+) и iOS 15 и новее.
- Игровое поле портретное. Референсный макет — 1080×1920. Поддерживаем мышь и касание, учитываем безопасные зоны. Проверяем интерфейс при 320×568, 360×800 и 390×844 логических пикселях на телефонах и в окне браузера 1280×720 на ПК.
- При запуске сразу открывается единственная карта первого уровня. Игрок строит и улучшает башни, вручную запускает каждую из десяти волн и получает награду за завершённые волны.
- Игрок побеждает, если база выжила после десятой волны, и проигрывает, когда здоровье базы падает до нуля. Оба экрана результата показывают итоговую волну, состояние базы и кнопку повтора. [DEV-01 в TowerDefence](https://app.notion.com/p/418ae71dc341815d8282e4ebbdf4fb77)

## Правила тестирования и приёмки

При приёмке первого уровня агент QA / плейтестер проверяет реализацию по обязательным критериям DEV-01 в рамках DEV-23. [Требования DEV-01](https://app.notion.com/p/418ae71dc341815d8282e4ebbdf4fb77) · [Проверка DEV-23](https://app.notion.com/p/418ae71dc341815cab10c9c78b7057a6)

1. Проверить запуск веб-сборки в согласованных браузерах и нативных сборок на минимальных поддерживаемых версиях Android и iOS.
2. На согласованных размерах проверить портретную компоновку, доступность основных кнопок и показателей, безопасные зоны, выбор площадки и башни мышью и касанием на соответствующих устройствах.
3. Проверить открытие карты сразу после запуска, строительство и улучшение башен, ручной запуск каждой из десяти волн и награду за каждую завершённую волну. Проверить победу после десятой волны при живой базе и поражение при нулевом здоровье базы.
4. На обоих итоговых экранах проверить номер волны, состояние базы и запуск нового матча на той же карте по кнопке повтора.

Для каждого критерия в DEV-23 указать сборку, платформу, ожидаемое и фактическое поведение и результат `PASS`, `FAIL` или `NOT RUN`. Приёмка завершена, когда все обязательные критерии подтверждены.

## Запуск Unity из чистой копии

1. Открой папку репозитория через Unity Hub в **Unity 6000.6.3f1**. Точная версия указана в [ProjectVersion.txt](ProjectSettings/ProjectVersion.txt).
2. Дождись импорта ресурсов и компиляции. Unity восстановит зависимости из `Packages/manifest.json` и `Packages/packages-lock.json` и создаст локальную папку `Library`.
3. Открой `Assets/Game/Scenes/Bootstrap.unity` и нажми Play. Сцена загрузит `Level01`.
4. Для проверки данных и анимаций используй команды **First Game → Validate Waves** и **First Game → Validate Tower Spine Animations**.

Git хранит `Assets` вместе с файлами `.meta`, `Packages` и `ProjectSettings`. Кэши, локальные настройки редактора и выходные сборки исключены через [.gitignore](.gitignore).

## Агенты First Game

Пять ролей Codex для Unity-проекта First Game (Glow Path Defense) ведут задачи в [Проекты / TowerDefence](https://app.notion.com/p/418ae71dc34180a4a1b0f4ce6ba9c63d). Notion используется только в процессе разработки.

| Роль | Результат |
|---|---|
| Продуктовый аналитик | Проверенная постановка и критерии приёмки |
| Системный аналитик | План и связанные карточки декомпозиции |
| Геймдизайнер | Правила механики, параметры баланса и сценарии плейтеста |
| Unity-разработчик | Изменения клиента и результаты локальных проверок |
| QA / плейтестер | Результаты проверки критериев и дефекты |

## Запуск

В корне Unity-проекта должны быть [AGENTS.md](AGENTS.md) с правилами маршрутизации и пять TOML из `.codex/agents/` этого пакета. При переносе в проект с существующим `AGENTS.md` добавь правила к нему. Открой новый чат из корня First Game с подключённым плагином Notion. Роли используют модель и инструменты сессии. [Документация Codex](https://learn.chatgpt.com/docs/agent-configuration/subagents)

1. В `All Issues` найди значение поля `Номер`. Для однозначного выбора установи `Роль агента` в карточке или укажи нужное действие в сообщении.
2. Напиши «Давай сделаем карточку номер 12», «Декомпозируй карточку 12» или «Проверь карточку 12». Вместо номера можно передать ссылку. Номера в примерах условные.
3. Роль заполнит постановку и добавит результаты к карточке. Готовая аналитика и дизайн переходят в `In review`, реализация — в `Testing`. QA ставит `Resolved` после выполнения критериев. Связанные находки оформляются в `Backlog`.

Для следующего этапа дай отдельную команду. Например, после реализации напиши «Проверь карточку 12». Статус `Testing` сам по себе следующий запуск не инициирует. Все правила по статусам и карточкам описаны в [AGENTS.md](AGENTS.md).
